# 要件定義: ページ認証の防御深度強化

- 日付: 2026-03-29
- 関連Issue/PR: advice.md（URL直接アクセスによる認証バイパスの懸念）

## 目的

各ページに個別の認証チェックを追加し、app.pyの認証ゲートに加えた防御深度（defense-in-depth）を実現する。

## 背景

- 現在、認証はapp.pyの`require_login()`のみで集中管理されている
- `st.navigation()` APIの仕様上、全リクエストはapp.pyを経由するため**現時点で直接のバイパスは不可能**
- しかし防御深度の観点から、各ページにも認証チェックを追加すべき

## 受け入れ条件

- [x] pages/00〜05の全ページのmain()冒頭で認証チェックを実施
- [x] 未認証時はエラー表示+st.stop()で即座に停止
- [x] 管理者ページは既存の`_require_admin()`に加え、基本認証チェックも実施
- [x] 既存テストが全て通過すること

## 対象スコープ

- src/utils/auth.py（ヘルパー関数追加）
- src/pages/00_dashboard.py〜05_admin.py

## スコープ外

- 認証フロー自体の変更
- セッション管理の変更
