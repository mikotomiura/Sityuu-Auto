# 設計メモ: パスワードリセット機能

- 日付: 2026-03-29

## 実装アプローチ

既存の招待トークン（InvitationRepository）と同じアーキテクチャパターンを踏襲する。
管理者がリセットトークンを発行 → URLとしてユーザーに共有 → ユーザーがURLアクセスでパスワード再設定。

### フロー

1. 管理者が管理者ページで対象ユーザーを選択し「パスワードリセットリンクを生成」
2. システムがトークンを生成し、URLを表示
3. 管理者がURLをユーザーに共有（口頭・チャット等）
4. ユーザーがURL（`?reset_token=xxx`）にアクセス
5. auth.py がクエリパラメータを検知し、リセットフォームを表示
6. ユーザーが新パスワードを入力・確認
7. パスワード更新 → トークン使用済み → ログイン画面にリダイレクト

## 変更内容

| ファイル | 変更内容 |
|---------|---------|
| `config.py` | リセットトークン関連の定数追加 |
| `models.py` | PasswordResetTokenRecord データクラス追加 |
| `migrations/007_*.sql` | password_reset_tokens テーブル作成 |
| `repositories/password_reset_repo.py` | トークンCRUD（create/validate/use/find_all/delete） |
| `auth.py` | リセットフォーム表示・require_login にリセットフロー追加 |
| `pages/05_admin.py` | リセットリンク発行タブ追加 |

## 代替案

1. **メール送信方式**: ローカルファーストの制約に反するため却下
2. **管理者による直接パスワードリセット**: 管理者が一時パスワードを設定する方式。ユーザーが自分で設定できないためUXが劣る
3. **セキュリティ質問方式**: 追加のDB設計が必要かつセキュリティ的に脆弱

## 影響範囲

- `auth.py`: require_login() にリセットトークン検知を追加
- `05_admin.py`: 新タブ追加
- DBスキーマ: 新テーブル追加（既存テーブルへの変更なし）
