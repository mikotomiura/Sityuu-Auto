# 機能設計書（functional-design.md）

## 1. システム概要

### 1.1 システムの目的

出品者（メンター）が相談者の生年月日を入力し、四柱推命・算命学の命式を瞬時に算出、AIが鑑定テキストのベースや傾聴のヒントを出力するローカルファーストシステム。

### 1.2 ユーザー

- **プライマリユーザー:** 出品者（メンター）1名
- **エンドユーザー:** なし（ローカル専用。相談者は直接システムを操作しない）

### 1.3 前提条件

- ローカルPC（Windows / macOS）でのみ稼働
- インターネット接続は LLM API 呼び出し時のみ必要
- サーバー維持費ゼロ
- SaaS化しない

## 3. 機能詳細

### 3.1 F-001: 相談者情報入力

**目的:** 命式算出とAI鑑定に必要な情報を収集する。

**入力項目:**

| 項目 | 型 | 必須 | バリデーション |
|------|----|------|----------------|
| お名前（仮名可） | テキスト | ✅ | 1〜50文字 |
| 生年月日 | 日付 | ✅ | 1900-01-01 〜 当日 |
| 出生時間 | 時刻 | ❌ | 00:00〜23:59（不明の場合は「不明」選択可） |
| 性別 | 選択 | ❌ | 男性 / 女性 / 回答しない |
| 現在の主な悩み | テキストエリア | ✅ | 10〜2000文字 |

**動作仕様:**
- 既存相談者の場合、名前入力時に候補をサジェスト表示
- 「鑑定開始」ボタン押下で命式算出処理（F-002）へ遷移
- 入力内容はセッションStateに保持し、ページリロードで消失しないようにする

---

### 3.2 F-002: 命式算出

**目的:** `lunar_python` を使用して四柱推命の命式を算出する。

**処理フロー:**
1. 生年月日を `lunar_python` の `Solar` オブジェクトに変換
2. `Solar` → `Lunar`（太陰暦）変換
3. `EightChar`（八字 = 四柱）を取得
4. 年柱・月柱・日柱・時柱の天干・地支を抽出
5. 各柱の五行属性を判定
6. 命式データオブジェクト（`NatalChart`）として構造化

**出力データ構造:**
```
NatalChart:
  year_pillar: Pillar(stem="甲", branch="子", element="木")
  month_pillar: Pillar(stem="丙", branch="寅", element="火")
  day_pillar: Pillar(stem="庚", branch="午", element="金")
  hour_pillar: Pillar(stem="戊", branch="申", element="土") | None
  day_stem: "庚"  # 日干（最重要）
  five_elements_balance: {木: 2, 火: 1, 土: 2, 金: 2, 水: 1}
```

---

### 3.3 F-003: 算命学データ算出

**目的:** 命式を基に算命学固有のデータ（十大主星・十二大従星・天中殺）を算出する。

**処理フロー:**
1. 日干と他の干支の関係から十大主星を算出
2. 十二支の組み合わせから十二大従星を算出
3. 年柱の干支から天中殺グループを判定
4. 人体星図の中心星・北方星・南方星・東方星・西方星を配置

**算出ルール:**
- 十大主星の算出: 日干と各柱の天干の関係（比和・相生・相剋）で決定
- 天中殺の算出: 六十干支の配列から空亡となる十二支の組み合わせを特定

---

### 3.4 F-005: AI鑑定テキスト生成

**目的:** 命式データと悩みを基にLLMが鑑定テキストのベースを生成する。

**システムプロンプト構成:**
```
[ロール定義]
あなたは熟練のカウンセラーであり、東洋占術（四柱推命・算命学）に精通した鑑定師です。

[タスク定義]
以下の命式が示す相談者の本質（強み・弱み）を踏まえ、この悩みにどう寄り添い、
どのような言葉をかければ相手の自己肯定感が高まるか、アドバイスのベースを作成してください。

[命式データ]
${natal_chart_formatted}

[相談者の悩み]
${concern_text}

[出力フォーマット]
1. 命式から読み取れる相談者の本質（3〜5行）
2. 悩みに対する占術的観点からの解釈（3〜5行）
3. 具体的なアドバイス案（3〜5項目）
4. 傾聴時の声掛けポイント（3〜5項目）
```

**API呼び出し仕様:**
- プロバイダー: OpenAI API or Anthropic API（設定で切替可能）
- モデル: GPT-4o / Claude 3.5 Sonnet（設定で変更可能）
- max_tokens: 2000
- temperature: 0.7
- タイムアウト: 30秒
- エラー時: リトライ1回 → 失敗時はエラーメッセージ表示

---

### 3.5 F-008: セッション保存

**目的:** 鑑定結果をローカルDBに永続化する。

**保存データ:**
- 相談者ID（UUID）
- セッションID（UUID）
- 入力データ（名前・生年月日・出生時間・悩み）
- 命式データ（JSON形式）
- AI生成テキスト
- 出品者メモ（任意入力）
- 作成日時
- 更新日時

## 5. 非機能要件

| 項目 | 要件 |
|------|------|
| 応答時間 | 命式算出: 1秒以内、AI生成: 30秒以内 |
| データ保存 | SQLite ファイルサイズ上限なし（ローカル制約に依存） |
| 同時利用者 | 1名（ローカル専用） |
| バックアップ | SQLite ファイルの手動コピーで対応 |
| セキュリティ | APIキーは `.env` で管理、個人情報はローカル保存のみ |
| 対応OS | Windows 10+, macOS 12+ |
| Python | 3.11 以上 |
