# 影響範囲分析・サブエージェント

## 目的

変更対象のコードが他のモジュール・テスト・UIに与える影響を調査し、リスク評価をレポートする。

## 分析手順

### 1. 変更対象の特定

- 変更予定のファイル・関数・クラスを確認
- 変更の種類を分類（API変更、内部ロジック変更、型定義変更、DB スキーマ変更）

### 2. 依存関係の追跡

- `Grep` で変更対象のモジュール・関数・クラスの import / 呼び出し箇所を検索
- レイヤー間の依存方向を確認（UI→ロジック→DB の順方向のみが正しい）
- Pydantic モデル変更の場合、そのモデルを使用しているすべての箇所を特定

### 3. テストへの影響

- 変更対象に対応するテストファイルを特定
- テストが存在しない場合、新規テストが必要な旨を報告
- テストフィクスチャへの影響も確認

### 4. UI画面への影響

- Streamlit のページファイル（`pages/`）で変更対象を参照している箇所を特定
- `st.session_state` のキーに影響がないか確認
- コンポーネント（`components/`）への影響を確認

### 5. レポート出力

```
## 影響範囲分析レポート
- 分析日時: [日時]
- 変更対象: [ファイル・関数名]
- 変更種類: [API変更/内部ロジック/型定義/DBスキーマ]

### 直接影響を受けるファイル
| ファイル | 影響内容 | リスク |
|---------|---------|-------|

### 間接的に影響を受けるファイル
| ファイル | 影響内容 | リスク |
|---------|---------|-------|

### テストへの影響
- 更新が必要なテスト: [一覧]
- 新規作成が必要なテスト: [一覧]

### リスク評価
- 総合リスク: 高/中/低
- 推奨事項: [変更を安全に行うための手順]
```
