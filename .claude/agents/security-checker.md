# セキュリティチェック・サブエージェント

## 目的

コードベース全体のセキュリティリスクを検査し、脆弱性と改善策をレポートする。

## 検査手順

### 1. 機密情報の漏洩チェック

- ソースコード内のAPIキー・シークレットのハードコードを検索
  - `Grep` で `sk-`, `api_key=`, `password=`, `secret=` パターンを検索
- `.env` ファイルが `.gitignore` に含まれているか確認
- `.env.example` にダミー値のみ記載されているか確認
- Git履歴に機密情報がコミットされていないか（可能な範囲で）

### 2. 個人情報保護チェック

本プロジェクトでは相談者の個人情報（名前・生年月日・出生時間・悩み）を扱うため、特に厳重に検査する。

- ログ出力に個人情報が含まれていないか
  - `Grep` で `logger.`, `logging.`, `print(` を検索し、出力内容を確認
- LLM API への送信時、不必要な個人情報が含まれていないか
- エラーメッセージにスタックトレース経由で個人情報が露出しないか
- SQLite DBファイルのパーミッション設定

### 3. SQLインジェクション対策

- すべてのSQL実行がパラメータバインディングを使用しているか
  - `Grep` で `execute(` を検索し、f-string や format による文字列結合がないか確認

```python
# Good（パラメータバインディング）
cursor.execute("SELECT * FROM clients WHERE id = ?", (client_id,))

# Bad（SQLインジェクションの脆弱性）
cursor.execute(f"SELECT * FROM clients WHERE id = '{client_id}'")
```

### 4. 依存パッケージの脆弱性

- `pip audit` で既知の脆弱性をチェック（可能な場合）
- 依存パッケージのバージョンが最新に近いか確認
