# API連携 開発規約

## クライアント設計

### Strategy パターンの採用

- `LLMClient` 抽象基底クラスを定義し、OpenAI/Anthropic を切替可能にする
- ファクトリ関数 `create_client(provider)` でインスタンスを生成する
- 新しいプロバイダー追加時は、`LLMClient` を継承した新クラスを追加するだけでよい

### 設定の外部化

- APIキー: `.env` ファイルで管理（`python-dotenv` で読み込み）
- モデル名: `src/config.py` でデフォルトを定義、設定画面で変更可能
- タイムアウト: 30秒（`config.py` で定数定義）
- max_tokens: 2000（`config.py` で定数定義）

## プロンプト構築のルール

### テンプレートの管理

- プロンプトテンプレートは `src/ai_service/templates/` にマークダウン形式で保存
- 変数は `${variable_name}` 形式で埋め込む
- テンプレートの変更はDBにも保存し、ユーザーがカスタマイズ可能にする

### プロンプトの構成

1. ロール定義（あなたは〇〇です）
2. タスク定義（以下の情報をもとに〇〇してください）
3. 入力データ（命式データ、悩みテキスト）
4. 出力フォーマット指定（番号付きリスト等）
5. 制約条件（文字数制限、禁止事項等）

### 個人情報のマスキング

- LLM API に送信する際、相談者の本名を仮名/イニシャルに置換するオプションを提供
- 生年月日は命式算出に必要なため送信するが、そのままではなく命式データとして送信

## エラーハンドリング

### リトライ戦略

- API呼び出し失敗時: 1回リトライ（合計2回試行）
- リトライ間隔: 2秒
- 2回目も失敗した場合: `AIServiceError` を送出

### エラー分類と対応

| エラー種別 | 対応 |
|-----------|------|
| APIキー未設定 | `AIServiceConfigError` を送出 → 設定画面へ誘導 |
| 認証エラー（401） | `AIServiceConfigError` を送出 → APIキーの確認を促す |
| レート制限（429） | 待機時間を表示 → ユーザーにリトライを促す |
| タイムアウト | リトライ → 失敗時は命式のみ表示（AI部分なし） |
| サーバーエラー（5xx） | リトライ → 失敗時はエラー表示 |
| ネットワークエラー | オフライン検知 → 命式のみ表示モードに切替 |

### レスポンスのバリデーション

- AIのレスポンスが期待する構造であることを検証する
- 空レスポンスや不正なフォーマットの場合はエラーとして扱う
