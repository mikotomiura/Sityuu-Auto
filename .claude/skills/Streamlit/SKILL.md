# Streamlit 開発規約

## ページ構成のルール

### マルチページ構成

- エントリーポイントは `src/app.py`
- 各ページは `src/pages/` に `[番号]_[名前].py` の形式で配置
- ページ番号はナビゲーション順序を表す

### ページファイルの責務

ページファイルはコンポーネントの「組み立て」に徹し、ビジネスロジックを直接記述しない。

## 状態管理のルール

### session_state の使用方針

- `st.session_state` をアプリケーション唯一の状態管理手段とする
- 状態キーは `src/config.py` に定数として定義する
- 状態キー名は `UPPER_SNAKE_CASE` で命名する
- 状態の初期化は各ページの先頭で行う

### 状態キーの命名規則

```
SESSION_KEY_[カテゴリ]_[詳細]
```

例: `SESSION_KEY_CLIENT_CURRENT`, `SESSION_KEY_CHART_RESULT`

## コンポーネント設計のルール

### コンポーネントの定義

- 再利用可能なUI部品は `src/components/` に関数として切り出す
- 関数名は `render_[コンポーネント名]` とする
- 戻り値は、ユーザー入力を返す場合はその値、表示のみの場合は `None`

### コンポーネントの型ヒント

- 引数と戻り値に必ず型ヒントを付与する
- Streamlit 固有の型（`DeltaGenerator` 等）も適切に使用する

## キャッシュ戦略

### @st.cache_data

- 計算結果やデータの変換結果に使用する
- 命式算出結果のキャッシュに使用する
- 引数がハッシュ可能であることを確認する

### @st.cache_resource

- DB コネクションなどのリソースに使用する
- シングルトン的に使い回すオブジェクトに使用する

## UI表示のルール

### ローディング表示

- 1秒以上かかる処理には `st.spinner()` を使用する
- API呼び出し中は `st.spinner("AIが鑑定テキストを生成中...")` のようにユーザーに状況を伝える

### エラー表示

- バリデーションエラー: `st.warning()` を使用
- 処理エラー: `st.error()` を使用
- 成功通知: `st.success()` を使用

### 個人情報の表示

- 相談者情報は画面上に表示してよいが、URL パラメータには含めない
- ブラウザのコンソールログに個人情報を出力しない
